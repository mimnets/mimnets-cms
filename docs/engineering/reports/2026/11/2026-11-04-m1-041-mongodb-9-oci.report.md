## Security observations

- **Open MongoDB on the owner's OCI server (finding 2).** Anyone on the internet can read, change
  or delete data on it. It holds no project data. The agent's `docker stop mongodb` was refused
  by the Claude Code permission check (interference with a running workload); the container was
  left running and the owner was given the command. **Still open at the end of the task**
  (re-checked from the agent's PC). Owner action: stop the container or recreate it bound to
  `127.0.0.1` with access control on, and remove any OCI ingress rule for 27017.
- Other containers on the same server are also published on all interfaces. They are outside
  this project and were neither probed nor changed; the owner was told in session.
- The server's address and service list are kept out of tracked files, because the server was
  reachable without authentication.
- The `latest` image tag moves between major versions; pin a patch tag on any server the
  project depends on.
- No secrets are recorded in this task. No database credentials were created.

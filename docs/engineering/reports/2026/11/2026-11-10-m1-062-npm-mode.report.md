## Status

**The NPM mode is built and passes every local check against a stand-in for NPM.** Not tested with NPM
itself, on a server, over IPv6, or with a real certificate. The standalone mode (D-DB-17 option A) is
unchanged and was rechecked.

## Changes

| File | Change |
|---|---|
| `docker/staging/compose.npm.yaml` (new) | Override for `-f compose.yaml -f compose.npm.yaml`: `nginx.ports: !reset []`; nginx joins the external network `${ASSURER_NPM_NETWORK:-assurer-npm}` at `${ASSURER_NPM_NGINX_IP:-172.30.56.10}`; `ASSURER_UPSTREAM_PROXY_IP` required, no default; `certbot` moved to a `standalone` profile, so it does not start |
| `docker/staging/nginx/assurer-npm.conf.template` (new) | The `:8080` server of paper §4.2 and §4.3: `real_ip` from NPM's address only (`X-Real-IP`), the site's host name only (others 444), same upload limit, rate limit and proxy headers as the 443 block (duplicated, with a "keep in step" comment, so the tested 443 block is untouched) |
| `docker/staging/nginx/35-assurer-npm.sh` (new) | Start script: renders that template to `conf.d` only when `ASSURER_UPSTREAM_PROXY_IP` is set; refuses anything but one IPv4 address (a range, a list or a newline stops nginx from starting) |
| `docker/staging/nginx/Dockerfile` | Copies the two files. The template sits outside `templates/`, so the image's own envsubst step never renders it |
| `docs/runbooks/staging-container.md` | New §9 "NPM mode": what changes, settings, the owner's steps on NPM, start, checks; a §8 row; `compose.npm.yaml` in Files |

The template choice left open by the paper (§5): a second template rendered by the image when the
variable is set, rather than one mounted by the override, so the image is self-contained.

`--internal` is recommended for `assurer-npm` (runbook §9 step 1). NPM keeps its own network for
Let's Encrypt; the stand-in forwarded over an internal network without trouble.

## Tests executed and actual results

On `linux/amd64` (Docker Desktop, Compose v5.7.0), disposable project `m1062`. Only the nginx image
was rebuilt; the site image `assurer-site:staging` (2026-11-09) was used as is, since no app code
changed after it. Settings: `ASSURER_DOMAIN=localhost`, `APOS_BASE_URL=https://localhost:8443`, network
`m1062-npm` (`172.30.56.0/24`, `--internal`).

**Stand-in for NPM** (owner's choice, no new image): a container from `assurer-nginx:staging` with a
config copying the parts of NPM v2.16.0 the design depends on (paper §3): `set_real_ip_from` the three
private ranges, `real_ip_header X-Real-IP`, `real_ip_recursive on` (`IP_RANGES_FETCH_ENABLED=false`),
`X-Real-IP $remote_addr`, appended `X-Forwarded-For`, `client_max_body_size 2000m`, a self-signed TLS
certificate for `localhost`. At `172.30.56.2` on `m1062-npm`, published on `127.0.0.1:8443`. Test
visitors came from containers on a second network with a **non-private** test subnet
(`198.51.100.0/24`), so the stand-in treated them as internet visitors.
